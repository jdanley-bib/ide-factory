# Design

## Context

See proposal.md for why this change exists. `idefactory pr open` already creates branch `factory/<change>` when that local branch is missing, writes `.factory/pull-requests/<change>.json`, and asks the forge to open one pull request. The record stores `change`, `branch`, and `pullRequest.number` plus `pullRequest.url`. A second open updates that same pull request. `pr open` does not push and does not merge.

`readPullRequestRecord` in `src/lib/pull-request.mjs` returns that record only when `change` matches and `pullRequest.number` is an integer. Init copies `templates/skills/` into the IDE skill directories and copies `templates/cursor/rules/factory.mdc`, `templates/cline/rules/factory.md`, and `templates/copilot/factory.agent.md` into the installed adapters. The OpenSpec archive skill is generated by OpenSpec. This change does not depend on editing that generated file.

## Goals / Non-Goals

**Goals:**

- One guidance text, installed from the factory templates, that the agent reads before it touches a pull request or a human-gated command.
- One predicate, `isDeliverableChange`, that archive guidance and the stage 1 exit test both use.
- A missing, incomplete, or wrong-branch record fails that predicate and leaves the change directory in place.

**Non-Goals:**

- A second pull-request command, or a merge command.
- Rewriting `pr open` so that it pushes. Pushing `factory/<change>` stays an ordinary git push so the existing forge create can see the branch. Push is not a legal pull-request step and does not replace `pr open`.
- Backfilling records for pull requests that were not opened by `pr open`.
- Editing the evolution plan document. The exit test calls this predicate; the plan file stays where it is.

## Decisions

### Put the rules in the templates the installer copies

Add the same short rules to `templates/skills/factory-coordinator/SKILL.md`, `templates/skills/factory-run/SKILL.md`, `templates/skills/factory-openspec/SKILL.md`, and `templates/skills/factory-governance/SKILL.md`, and to the three rule templates (`templates/cursor/rules/factory.mdc`, `templates/cline/rules/factory.md`, `templates/copilot/factory.agent.md`).

The rules say:

- The only legal pull-request steps are `idefactory pr open <change>`, `idefactory pr comment <attemptId>`, and `idefactory pr capture <change>`.
- The agent never merges, and it does not open or edit a pull request through the Cursor pull-request tool or a hand-written `gh pr create` or `gh pr edit`.
- `sync-tasks`, `run`, `approve`, `complete`, `verify`, `ci scaffold`, and archive or spec sync run only after the human asks for that action.

Upgrade already recopies these templates. A temp-project init test reads the installed Cursor rule and the installed factory-run skill.

Alternatives considered:

- Edit only the generated OpenSpec archive skill. Rejected. OpenSpec can regenerate it, and the always-applied factory rule would still omit the rule.
- Add a new slash command for the rules. Rejected. The agent already loads the factory rule and these skills.

### One predicate reads the record `pr open` writes

Add `isDeliverableChange(project, change)` beside `readPullRequestRecord`. It is true only when that function returns a record whose `branch` is `factory/<change>`, whose `pullRequest.number` is a positive integer, and whose `pullRequest.url` is a non-empty string. Anything else is false, including a missing file.

Assumption: the schema `pr open` writes is the proof that the command produced the record. This change does not add a signature. A file with a different branch, or without a number or URL, fails.

Factory-openspec and factory-coordinator say: when the human asks to archive, run this check first. If it is false, stop and do not move `openspec/changes/<change>/`. Spec sync stays human-gated the same way and does not itself require the record. The stage 1 exit test calls the same predicate for each change under test and fails that change when the predicate is false.

Alternatives considered:

- Treat any JSON file under `.factory/pull-requests/` as enough. Rejected. A cursor-branch record would look deliverable, which is the gap this change closes.
- Make archive a new `idefactory archive` command. Rejected. Archive stays the OpenSpec move. The factory only refuses to perform it without the record.

### Cloud agents use a runtime GH_TOKEN

`idefactory pr open`, `idefactory pr comment`, and `idefactory pr capture` call the GitHub CLI. On a Cursor cloud agent, the Cursor GitHub App token is not sufficient for those commands. The agent needs a Cursor environment runtime secret named `GH_TOKEN`. The secret is a fine-grained personal access token limited to this repository, with contents read and write, pull requests read and write, and metadata read. This change names that secret and those permissions. It does not include a token value, and it does not commit a dotenv file or any other credential file.

Later Azure DevOps and Zoho credentials use that same pattern: Cursor environment runtime secrets, not committed files. This change does not add those integrations.

Alternatives considered:

- Reuse the Cursor GitHub App installation token. Rejected. That token cannot run the pull-request commands this change requires.
- Commit the token, or write it into the change. Rejected. Credentials stay runtime secrets.

## Risks / Trade-offs

- [The generated OpenSpec archive skill does not mention the predicate] → The factory rule and factory-openspec do, and those are what init installs. The agent stops before the move when the check fails.
- [A hand-written file that copies the `pr open` shape would pass] → The branch must be `factory/<change>`, and number and URL must be present. This change does not add a signature.
- [The five merged changes have no records, so the stage 1 exit test still fails] → This change does not invent those records. The stage stays failed until real `pr open` records exist.
- [A cloud agent without `GH_TOKEN` cannot open, comment, or capture] → The secret is set on the Cursor environment. This change does not embed a token. The Cursor GitHub App token does not replace it.

## Migration Plan

No data migration. Existing projects gain the guidance on the next init or upgrade. Rollback is reverting the template text and the predicate.

## Open Questions

None. The predicate and the guidance text above are what the tasks implement.
