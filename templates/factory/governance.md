# Governance

Operational baseline for the IDE factory. Agents may read this file. Prefer append-only updates to decisions and histories.

1. **Human-authored scope.** The human authors OpenSpec changes. The factory does not invent product scope.
2. **IDE models only.** he IDE session the human opened is the only model budget.
3. **Authorize before external effects.** Approvable actions are `accept`, `complete`, `publish`, `deploy`, `spend`, and `account`. `accept` and `complete` are gates bound to a task and a clean source revision, and a profile `humanGate` of false waives them. `publish`, `deploy`, `spend`, and `account` are external effects bound to a change and a `--target`, and no profile waives them. Before a step with an external effect, run `idefactory authorize --change <name> --action <action> --target <name>`. Continue when it reports `authorized: true`. Stop and report the `reason` when it reports false. A human records authority with `idefactory approve`, either per task or as a standing authorization (`--standing`, policy version 2, capped by `governance.standingMaxHours`), and can end it with `idefactory revoke`. Do not ask the human whether to proceed when `authorize` already says yes.
4. **Honest verification.** Do not claim a check passed unless you ran it and it passed. A skipped check is not a pass.
5. **Append-only memory.** Do not truncate `.factory/decisions.md` or agent histories. Append.
6. **Kill switch.** If a file named `HALT` exists in the project root, stop factory commands.
7. **Protected paths.** Do not rewrite `.factory/decisions.md` or agent histories in place. Charters change only with explicit roster refresh (`--force-roster`).
8. **Reviewer differs.** The reviewer is a different role from the implementer.
9. **Prefer common tools.** Use maintained scaffolds, frameworks, and libraries before hand-rolling. Examples: `npm create vite@latest` for a SPA, official CLIs for apps, standard test runners. Invent a custom toolchain only when the OpenSpec design explicitly requires it.
10. **Work queue.** `.factory/work/` is the only execution queue. OpenSpec `tasks.md` is the human plan.
11. **One writer.** One IDE session writes `.factory/` at a time. Git merges concurrent edits.
12. **Red exceptions.** A rejected attempt's genuine red may be reused with `idefactory red reuse`, or a red waived with `idefactory red waive`, only when a human authorizes it and the approver is not the implementer. Waiving a red before the system is stuck is discouraged. Prefer reuse, and let the attempt hit `vacuous-red` first. Pass `--acknowledge-not-stuck` only after the human acknowledges that warning. An exception never claims a red ran and never waives clean-revision verification, independent review, or lockouts. A failing red recorded after implementation is not test-first evidence: a human can invalidate it with `idefactory red waive --invalid-red "reason"`, which then does not satisfy red. Reds are append-only. After an invalidation, one later failing red for that kind is allowed and satisfies red when it starts after the waiver, but it does not prove the test came first, so the reviewer judges that from `idefactory red list`.
13. **Red method.** `red-first` is the default. An implementing agent may record a `no-red` method with `idefactory method propose` when a failing test cannot specify the change, naming one reason class (`docs-or-text`, `configuration`, `behavior-preserving`, `mechanical`, `exploratory`) and a rationale. A different role must accept it with `idefactory method review`. No human approval is needed, an explicit `factory.taskType` is never overridden, and a method is not a red that ran or a red exception. It does not waive passing verification, independent review, lockouts, or human gates.
14. **Reopen.** `idefactory attempt reopen` moves an `accepted` attempt back to `awaiting-review` for named kinds that lack a red, method, or exception, with `--for method` or `--for exception`, an identity other than the implementer, and a reason; under policy version 2 the identity must be a verified principal. It is allowed at most twice, never after finalization starts, and the earlier review stays in the review history without counting. It is not a substitute for review, passing verification, lockouts, or human gates.

Spend, publishing, deployment, and new accounts need an approval that `idefactory authorize` confirms. A `HALT` file stops `sync-tasks`, `next`, `run`, attempt mutations, and `complete`.
